# 🚀 Telegram Auto-Poster System

## Професійний пошук груп (Reddit / OFM)

Перед запуском оновленого парсера виконайте у Supabase SQL Editor файл
`database/migrations/20260916_continuous_discovery.sql`. Це окрема додаткова міграція:
вона зберігає чати, оголошення та історію. Старі незавершені сесії пошуку позначаються
перерваними. Для оновлення не потрібно повторно виконувати весь `schema.sql`.

Оновіть залежності командою `pip install -r requirements.txt` і перезапустіть
`python main.py`. Підтримується один процес / один ASGI worker. Не запускайте кілька
копій застосунку з тією самою Telegram-сесією. Пошук використовує наявний авторизований
акаунт; не запускайте `main.py` лише для тестування, якщо у БД увімкнена розсилка.

У вкладці «Пошук & Парсер чатів» задайте слова та мінімум учасників. «Почати пошук»
запускає серверну задачу; «Стоп» завершує її. Закриття вкладки не зупиняє пошук.
Після перезапуску сервера незавершений пошук відновлюється з урахуванням збереженої
паузи Telegram. Якщо сервер недоступний, пошук не виконується.

Цільова аудиторія: агенції, OFM, чатери та спеціалісти з adult-трафіку — покупці
Reddit-акаунтів і просування моделей. AI аналізує текст опису та до 30 доступних
повідомлень, без завантаження медіа чи списків учасників. До Gemini передаються ці
тексти для погодженої перевірки; у БД залишаються короткі цитати й висновок.
Назва без професійного контенту не є підтвердженою відповідністю. Правила реклами,
доступ до публікації та відповідність аудиторії відображаються окремо.

Усі публічні знахідки зберігаються за Telegram ID до аналізу контенту. Вже знайдені,
приховані та відхилені чати не повертаються у новій видачі; вони доступні в історії.
Незавершені перевірки залишаються у фільтрі «Не перевірені». Старі записи, створені
попередньою версією без Telegram ID, зіставляються за username і отримують ID при
повторному виявленні; стару зміну username без збереженого ID встановити неможливо.

Невідома кількість учасників не вважається нулем і не проходить позитивний поріг.
Зміна порога у новому пошуку не повертає старі знахідки — для них використовуйте історію.
Пошук каталогу Telegram обмежений доступною видачею; глобальний пошук повідомлень
перегортається зі збереженням курсора. Між RPC діє пауза 4–8 секунд, між повними
циклами — 5 хвилин; FloodWait завжди має пріоритет. Нескінченної кількості нових груп
це не гарантує. Пошук не вступає у групи й не публікує оголошення.

Налаштування в `.env.example`: `GEMINI_MODEL`, `DISCOVERY_RPC_MIN_SECONDS`,
`DISCOVERY_RPC_MAX_SECONDS`, `DISCOVERY_CYCLE_SECONDS`. Без ключа Gemini або при
помилці AI працює консервативний відбір за правилами; інтерфейс показує цей стан.

Перевірки без доступу до живих акаунтів:

```bash
python -m unittest discover -s tests -v
node --test tests/discovery_frontend.test.cjs
```

Окремі читальні перевірки сервісів: `python scripts/check_discovery_services.py`
та `python scripts/check_discovery_telegram.py --full`. Для перевірки інтерфейсу на
штучних даних: `python -m uvicorn scripts.preview_discovery:app --port 8017`.

Автоматизована система публікації рекламних оголошень у цільові групи та канали Telegram з індивідуальними інтервалами, хмарною базою даних Supabase, десктопною веб-панеллю в стилі Telegram та мобільним адмін-ботом.

   * 1 година (60 хв), 1 доба (24 год), 3 дні (72 год) або будь-який інший інтервал.
2. **Анти-фрод та безпека (Anti-Ban):**
   * Автоматичне виявлення `Slowmode` у чатах та адаптивне перенесення відправки.
   * `FloodWait` захист — очікування точного часу без ризику блокування.

   * 💻 **Desktop Web Dashboard:** Стилізований під автентичний Telegram Desktop Dark Mode з живим прев'ю повідомлення та масовим імпортом 50 чатів.

## 📋 Покроковий запуск

### 1. Створення таблиць у Supabase
1. Відкрийте ваш проект у [Supabase Dashboard](https://supabase.com/dashboard/project/lwkfsdyoynooympbidyr).
2. Перейдіть у розділ **SQL Editor** (зліва в меню).
3. Скопіюйте вміст файлу `database/schema.sql`, вставте його в редактор і натисніть **Run**.

### 2. Встановлення залежностей
```bash
pip install -r requirements.txt
```

### 3. Одноразова авторизація вашого Telegram акаунту
Запустіть інтерактивний скрипт авторизації:
```bash
python auth.py
```
* Введіть ваш номер телефону та код із Telegram (а також пароль 2FA, якщо він встановлений).
* Буде створено файл сесії `poster_session.session`.

### 4. Запуск комплексу
```bash
python main.py
```

* **Панель на ПК:** відкрийте у браузері [http://127.0.0.1:8000](http://127.0.0.1:8000)
* **Бот на телефоні:** відкрийте вашого бота в Telegram та надішліть йому `/start`.

### Поведінка автопостингу та відновлення після паузи

Недоступна група (заборона писати, бан у групі, приватний або неправильний
чат) вимикається окремо. Інші групи продовжують оброблятися. SlowMode переносить
час лише для відповідної групи; FloodWait призупиняє планувальник на вказаний
Telegram час із запасом. Три системні помилки поспіль усе ще спричиняють
аварійну паузу. Її причина зберігається в журналі та відображається в панелі.

Прострочений таймер означає місце в черзі, а не гарантію миттєвої відправки:
діють ліміти, паузи між публікаціями та відпочинок між серіями. Панель показує
поточну причину очікування, зокрема якщо планувальник не запущений.

Після оновлення перезапустіть процес `python main.py` та оновіть сторінку.
Якщо розсилку раніше було зупинено захистом, увімкніть її кнопкою в панелі
або адмін-боті. Оновлення коду саме не вмикає розсилку та не активує недоступні
групи. Окрема міграція БД для цього виправлення не потрібна.
Для одного акаунту запускайте один процес автопостера: локально або на сервері.

## 👥 Кілька акаунтів для розсилки

Крім основного акаунта (сесія з `TELEGRAM_STRING_SESSION` / файлу), можна підключити довільну кількість додаткових.
У кожного акаунта **свій список чатів**, власні погодинні/добові ліміти, пауза між серіями та аварійний запобіжник.
Варіанти постів спільні: будь-якому чату будь-якого акаунта можна призначити будь-який пост.

**Порядок розгортання на продакшн (одна БД з сервером):**
1. Виконайте в Supabase SQL Editor `database/migrations/20261015_multi_accounts.sql` (лише додає таблицю й колонки; існуючі дані не змінюються, стара версія продовжує працювати).
   Потім виконайте `database/migrations/20261017_account_worker_lease.sql` — без неї додаткові акаунти не запускаються (захист сесій, див. нижче).
2. Задеплойте нову версію коду на сервер.
3. Лише після цього додавайте акаунти та їхні чати. Стара версія коду публікує *всі* активні чати з основного акаунта, тому чати нових акаунтів, додані до оновлення сервера, вона б розсилала з основного.
4. (Опційно) Щоб один і той самий чат міг бути у списках різних акаунтів, після оновлення **всіх** інстансів виконайте `database/migrations/20261015_multi_accounts_phase2.sql`.

**Додавання акаунта:** веб-панель → «👥 Акаунти розсилки» → «+ Додати акаунт» (QR або номер + 2FA), або бот → «👥 Акаунти розсилки» → «➕ Додати акаунт» (номер; код вводьте з дефісами, напр. `1-2-3-4-5`, інакше Telegram анулює пересланий код).
Новий акаунт додається з **вимкненою** розсилкою: додайте йому чати (вкладка «Цільові чати» → вибір акаунта, або бот → картка акаунта → «➕ Додати чати») і увімкніть розсилку.

**Важливо:**
* Сесії додаткових акаунтів зберігаються в таблиці `accounts` (`session_string`) — вони так само секретні, як `SUPABASE_KEY`.
* Перед першим постом додатковий акаунт сам вступає в чат (за юзернеймом або інвайт-лінком). Якщо в чаті заявки на вступ — чат відкладається на 6 год з позначкою.
* Пости, завантажені зі «Збережених» основного акаунта, додаткові акаунти надсилають як HTML-текст (медіа з оригіналу недоступне іншому акаунту).
* **Одна сесія — один процес.** Telegram назавжди анулює сесію (`AuthKeyDuplicatedError`), якщо її використовують одночасно з двох IP (сервер + локальна копія, або старий і новий контейнер під час редеплою). Тому процес спершу бере в базі «оренду» акаунта (`worker_id` / `worker_heartbeat_at`), продовжує її кожні 15 с і зупиняє воркер, якщо не може її продовжити; інший процес чекає, поки оренда звільниться або протермінується (90 с). У картці акаунта видно, який хост зараз веде розсилку.
* Локальній копії з продовою БД однаково варто ставити `ACCOUNT_WORKERS_ENABLED=false`, щоб розсилка не «переїхала» на ваш комп'ютер, якщо він візьме оренду першим.
* Якщо сесію вже анульовано (статус «🔴 Сесію завершено»), відновити її неможливо: додайте той самий акаунт ще раз (QR або номер). Запис акаунта і його чати збережуться, оновиться лише сесія; потім увімкніть розсилку.
